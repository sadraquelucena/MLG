O problema da especificação

Considere um MLG com resposta \(Y\) e \(p\) variáveis preditoras: \[ g(\mu_i) = \eta_i = \beta_0+\beta_1 x_{i1}+\cdots+\beta_{p} x_{ip} \]

  • A inclusão de uma variável no modelo deve ser justificada por razões científicas, estatísticas ou práticas. Entre os principais aspectos, consideramos:
    • Relevância conhecida no fenômeno estudado
    • Estrutura de associação entre os preditoras (multicolinearidade)
    • Evidência estatística de associação com a resposta
    • Parcimônia
  • A seguir veremos ferramentas estatísticas para construção de um MLG. No entanto, precisamos ter em mente o seguinte:
    • Primeiro pensamos no modelo que faz sentido; depois usamos ferramentas estatísticas para avaliar e aperfeiçoar esse modelo.

Exemplo de especificação orientada pela teoria

  • Suponha que queremos modelar a probabilidade de inadimplência de um cliente.
  • Variáveis disponíveis: renda, dívida, idade, histórico de inadimplência, número de empréstimos, tempo de relacionamento e taxa de juros.
  • A teoria de risco de crédito sugere que a capacidade de pagamento e o histórico financeiro devem estar relacionados à inadimplência.
  • Por exemplo, a capacidade de pagamento pode ser representada pela razão dívida/renda: \(X_i=\frac{\text{Dívida}_i}{\text{Renda}_i}\).
  • Assim, podemos especificar:

\[ \log\left(\frac{\pi_i}{1-\pi_i}\right) = \beta_0 +\beta_1X_i +\beta_2\text{Inadimplência prévia}_i +\beta_3\text{Idade}_i. \]

Modelos candidatos

  • Em algumas situações, não existe uma especificação determinada pela teoria.
  • Se temos \(p\) variáveis candidatas (\(x_1,\ldots,x_p\)), cada variável pode enttrar ou não no modelo.
  • Com \(p=3\) preditoras (\(x_1,x_2,x_3\)) temos \(2^3=8\) submodelos possíveis:

\[ \begin{aligned} M_0 &: \eta=\beta_0\\ M_1 &: \eta=\beta_0+\beta_1x_1\\ M_2 &: \eta=\beta_0+\beta_2x_2\\ M_3 &: \eta=\beta_0+\beta_3x_3 \end{aligned} \]

\[ \begin{aligned} M_{12} &: \eta=\beta_0+\beta_1x_1+\beta_2x_2\\ M_{13} &: \eta=\beta_0+\beta_1x_1+\beta_3x_3\\ M_{23} &: \eta=\beta_0+\beta_2x_2+\beta_3x_3\\ M_{123} &: \eta=\beta_0+\beta_1x_1+\beta_2x_2+\beta_3x_3. \end{aligned} \]

  • Precisamos de uma estratégia para explorar e comparar esses modelos.

Como comparar modelos?

  • Não existe um único critério universal para definir o modelo mais adequado. Podemos considerar:

    • Critério do \(p\)-valor: utilizar testes de hipóteses para avaliar a contribuição das variáveis ao modelo.

      • Aqui mantemos apenas as variaǘeis com \(p\text{-valor}<\alpha\).

    • Critério de Informação de Akaike (AIC): equilibra qualidade do ajuste e complexidade do modelo. \[ AIC = -2\ell(\widehat{\boldsymbol{\beta}}) + 2k, \]

      • em que \(\ell(\widehat{\boldsymbol{\beta}})\) é a log-verossimilhança maximizada e \(k\) é o número de parâmetros estimados.
      • Regra de comparação: menor AIC \(\implies\) melhor modelo.

    • Critério científico: considera a teoria, o conhecimento substantivo e o objetivo da análise.

Estratégias de busca

  • Diferentes estratégias podem ser utilizadas para explorar os modelos possíveis:

    • Busca exaustiva: Ajusta todos os subconjuntos possíveis \(2^p\).
    • Forward: Começa com um modelo simples e adiciona variáveis.
    • Backward: Começa com um modelo completo e remove variáveis.
    • Stepwise: Permite adicionar e remover variáveis durante a busca.

  • É importante entender que \[ \boxed{\text{Estratégia de busca}\neq \text{critério de comparação}} \]

  • Exemplo: Podemos usar backward para explorar os modelos e AIC para decidir entre eles.

O procedimento na prática

  • 1. Especificar o modelo inicial
    • Definir as variáveis candidatas.
  • 2. Escolher uma estratégia de busca
    • Busca exaustiva, forward, backward ou stepwise.
  • 3. Definir o critério de comparação
    • AIC e/ou p-valor.
  • 4. Comparar os modelos candidatos
    • Considerar ajuste, complexidade e o critério de comparação escolhido.
  • 5. Avaliar o modelo escolhido
    • Diagnóstico dos resíduos, observações influentes, forma funcional e adequação das demais especificações.
  • 6. Reespecificar, se necessário

Exemplo 6.1

Considere o banco de dados birthwt, disponível no pacote MASS. Construa um modelo de regressão logística capaz de explicar a probabilidade de baixo peso ao nascer usando todos os preditores disponível no conjunto de dados.

Exemplo 6.1

Primeiro vamos organizar e traduzir o conjunto de dados.

library(MASS)

dados <- birthwt |>
  # remover bwt (peso de cada bebê)
  dplyr::select(-bwt) |>
  # codificar como fator as preditoras categóricas e renomear as demais
  dplyr::mutate(
    baixo_peso = low,
    idade = age,
    peso_mae = lwt,
    raca = factor(race, levels = c(1, 2, 3), labels = c("Branca", "Negra", "Outra")),
    fumante = factor(smoke, levels = c(0, 1), labels = c("Não", "Sim")),
    partos_prematuros = ptl,
    hipertensao = factor(ht, levels = c(0, 1), labels = c("Não", "Sim")),
    irritabilidade_uterina = factor(ui, levels = c(0, 1), labels = c("Não", "Sim")),
    consultas_pre_natal = ftv
  )

Exemplo 6.1

Ajustando o modelo completo e verificando se ao menos uma variável é importante no modelo.

# Modelo completo
modelo_completo <- glm(baixo_peso ~ idade + peso_mae + partos_prematuros +
  consultas_pre_natal + raca + fumante + hipertensao + irritabilidade_uterina,
  family = binomial(link = "logit"), data = dados)

# modelo nulo
modelo_nulo <- glm(baixo_peso ~ 1 , family = binomial(link = "logit"), data = dados)

# Teste da razão de verossimilhanças
lmtest::lrtest(modelo_completo,modelo_nulo)
